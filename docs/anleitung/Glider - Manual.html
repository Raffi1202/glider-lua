Glider

Flight display for gliders and electric gliders · Manual · Version 0.7.0 · 22 Nov 2026

Glider is a display (a “widget”) for FrSky radios with Ethos and a colour screen. On a full screen it shows vario, altitude, flight time, batteries and link, detects launch, release height and thermals and announces them. Every flight goes into a list with a summary, and you are warned when altitude, battery or link leave a limit you set.

Test status (version 0.7.0): Random test and 37 test runs in the Ethos simulator (X18RS, Ethos 26.2.0) passed, including settings and flight list after an update. Full screen 800 × 480 tested directly, 640 × 360, 480 × 320 and 480 × 272 simulated; compact view 784 × 316 directly, 630 × 258 and 472 × 210 simulated. On a real radio (X18RS, Ethos 26.2.0): start, three pages and announcements (0.1.1), sensor search with 48 sensors and reload (0.1.3/0.1.4). 0.4.0 (“Alarm also with motor off”, studio limits in a ring) and 0.3.1 (mute, motor battery, sensor list, steps, memory) only in the simulator so far. Lua-Studio (0.3.0) on the radio: example file, broken file, field errors, 10 model changes. Simulator only: menu changes (.funke.lua) and the full file with 16 places. 0.2.0: compact view with live telemetry, update from 0.1.4 and the changed search. The thermal gain is tested in the simulator only (it needs a detected flight). Not yet tested: real flight, radios other than the X18RS (simulator only).

1. What you need

  • A FrSky radio with Ethos 26.1 or newer and a colour screen (list in chapter 11).
  • A model with working telemetry and sensors already discovered (Model › Telemetry › Discover new sensors).
  • A vario with altitude and climb. Without a vario there is no flight detection, release height or thermal.
  • A computer with FrSky Suite and a USB cable.
  • The file Glider-0.7.0.zip. It is inside Glider-0.7.0-share.zip next to this manual. Unpack only the outer ZIP, not the inner one.

2. Install

  1. Switch on the radio and connect it to the computer with the USB cable.
  2. The radio shows a choice. Select Ethos Suite.
  3. Open FrSky Suite on the computer. The radio appears at the top.
  4. Click Lua-Bibliothek (Lua library), then Von lokaler ZIP installieren (install from local ZIP).
  5. Select Glider-0.7.0.zip. The Suite copies everything into the folder scripts/glider/ on the radio.
  6. Unplug the cable and restart the radio.

Without the Suite: connect the radio as “USB storage” and copy the folder glider from the ZIP into the folder scripts on the radio. Overwrite an existing folder, do not delete it.

3. Set up the screen

The widget needs a whole screen. Two layouts fit; the widget detects by itself which one you chose:

  • Full screen (one single large frame without bars): three pages with all values (chapter 5).
  • One frame with top and bottom bar: the compact view with the key values at a glance; Ethos keeps showing model name and radio battery at the top (chapter 5, “Compact view”).

In an even smaller frame it only shows “Area too small”.

  1. Tap the Screens icon at the bottom (two rectangles).
  2. Tap + at the top right.
  3. Scroll down to the layout Full screen (one single large frame) or one frame with top and bottom bar and tap it.
  4. Tap the empty frame, then Widget.
  5. Select Glider in the list. The frame now shows the display, without telemetry with dashes.
Glider in the widget list
No telemetry: grey “NO DATA”, dashes instead of numbers (German pictures)

You open the widget menu (all settings) at any time via Model › Screens › select screen › tap the widget.

4. Assign sensors

On first start the widget looks for the sensors itself as soon as telemetry is present. The blue bar at the top shows for 3 s “… sensors assigned automatically”. Check every line anyway:

  1. Power up the model so telemetry is running.
  2. Open the widget menu. At Find sensors (empty only) tap Search. The search runs within a few seconds after you close the menu; the result then appears in blue at the top of the display. Only empty lines are searched.
  3. Below every sensor found you see ID (Physical ID) and AppID, so sensors with the same name can be told apart. If it says “n sensors match, chosen: … - please check”, the Lua picked one of several matching sensors (first one with a value, otherwise the lowest number). Check that it is the right one.
  4. Open the groups Sensors, Batteries and Launch and release height and check every line. Select anything empty or wrong by hand.

Battery with cell sensor or total voltage only

For each battery the menu shows the line “Battery 1 detected” with “cell sensor” or “total voltage”. With a cell sensor (e.g. FrSky FLVSS) the widget measures every cell, shows it as a bar and warns by the lowest cell. With total voltage only, set Battery 1 cells (or 2, 3) to the cell count, e.g. 3S. The widget then uses the average cell (total voltage divided by cell count). While the cell count is “automatic”, menu and display show “Set cell count” and there is no cell warning for this battery.

Total voltage only, cell count not yet set (German picture)

Also select Battery 1 type (LiPo, LiFe, NiMH). Changing the type resets the cell limits of this battery: LiPo 3.50 / 3.30 V, LiFe 3.10 / 2.90 V, NiMH 1.15 / 1.05 V (warning / alarm).

The motor battery is monitored with every model type as soon as a sensor is assigned. The cell limits depend on the battery type (chapter 4).

Warning: orange, by default display only
Alarm: red, sound and voice, vibration

When it comes and goes: A warning appears when the value has been outside the limit for 1 second and disappears when it has been fine again for 3 seconds. So it does not flicker. After the model is powered up, everything stays quiet during the “Start delay” (default 10 s), so plugging in does not trigger an alarm.

What you hear: On an alarm the radio says the text and, with “Announce value”, the number, e.g. “Warning! Motor battery empty” and “18 percent”. It also vibrates. The call repeats every “Repeat every” (default 30 s) as long as the alarm lasts. Warnings are only announced with “Announce warnings too”. There are at least 3 seconds between two announcements; alarms come first. With the switch “Mute (switch)” events and warnings stay silent; red alarms still sound, the display remains. If “Mute” and “Motor off” use the same switch, the widget menu shows the note “Mute = motor off: alarms only” at the top.

An alarm is completely silent only when you switch it off. From 0.4.0 you can choose per value whether the alarm also sounds with the motor off (menu group “Alarm also with motor off”, on by default). Unticked, and with the switch “Motor off” at “Motor off at”, this alarm stays silent; the display keeps its colour. Lua-Studio can set the same (beiMotorAus).

7. Operation

Flight, release height and thermal

Start: A flight begins when altitude rises above “Flight starts above” (10 m) or the motor runs. End: It ends when altitude is below “Flight ends below” (5 m), the vario is calm (less than 0.5 m/s) and the motor is stopped, for “and calm for” (10 s). Then the blue bar at the top shows “Flight 3 saved” and the radio says “Flight saved”. Flights shorter than “Skip flights shorter” (30 s) do not go into the list.

Release height: With “Release height from” = “automatic” it is per launch type:

Launch typeRelease height is the altitude …
Towwhen the switch “Tow release” moves to the position “Released at” (default down).
E-launch (E-glider only)when the motor stops running (switch “Motor off” or throttle below the threshold).
Hand/winchat the highest point, when the model then sinks for “Highest point after sink” (3 s) and was higher than 10 m.

With “Tow release”, “Motor off” or “highest point” only that one type counts. The height shows in the blue bar, in the ALTITUDE tile and in the flight list; the radio says “Release height” and the number.

Thermal: When the model climbs at least “Announce from climb” (1.0 m/s) “for” (3 s) with the motor not running, “THERMAL +1.4 m/s” appears and the radio says “Thermal”. Then it stays quiet for “then quiet for” (30 s).

Thermal gain: From the moment the climb started, the widget counts the height gained and the time, e.g. “+85 m 1:22” (green while the thermal lasts). The thermal ends when the 20 s average drops below 0 or the motor runs; the value stays until the next thermal. You see it in the compact view, and in full screen when you set a tile or a bottom bar field to “Thermal gain”.

Altitude and flight time call-outs: Flip the switch “Announce alt. (switch)”: the radio says “Altitude” and the number. With “Announce alt. every” or “Announce time every” the call comes regularly.

View or delete a flight

  1. Go to the page Flights and tap a flight. You see launch type, release height, max altitude, climb/sink, flight time, motor run time, lowest receiver voltage and time per flight mode.
  2. Tap DELETE FLIGHT 2. “Delete flight 2?” appears.
  3. Tap YES, DELETE. Later flights move up one number. With CANCEL nothing changes. CLOSE returns to the list.

10. Update and remove

Renamed in 0.5.0: Segler is now called Glider (folder scripts/glider, Studio file id.glider.lua). This is a breaking change: choose the widget Glider again on every model and set it up again; the settings of the old widget are not taken over. Re-transfer Studio files from Lua-Studio or rename them; an old id.segler.lua is still read as long as no new file exists. The old folder scripts/segler can then be deleted.

Update: Install the new ZIP exactly as in chapter 2. The Suite only replaces the program. Your settings, sensors and the flight list are kept (folder daten/ in the script folder).

Remove: First take the widget off the screen (Model › Screens), then uninstall it in FrSky Suite under Lua-Bibliothek.

12. Lua-Studio: your own display per model

With the PC program Lua-Studio you design the display for each model yourself: which value goes where, as number, ring, bar (horizontal or vertical), curve or state, with your own colours, limits and settings. The studio writes one file per model to the radio, e.g. scripts/studio/M__we_2.glider.lua. The first part is the model id: the model name with every character other than A–Z, a–z and 0–9 turned into “_”. An umlaut counts as two characters and becomes “__” (“Möwe 2” becomes “M__we_2”). It is cut to 32 characters. Without this file Glider works exactly as before.

Own layout in the compact view (German pictures)
Own layout in full screen (replaces page 1)
  • Where the file may lie (0.6.0): Glider looks in scripts/studio/ of the script location, on the SD card (SD:/scripts/studio/) and in the radio memory (RADIO:/scripts/studio/), in this order.
  • Which file: The file starting with the model id (…glider.lua, see above) is taken automatically. If the name does not match the model, choose the file in the widget menu under Studio layout (all *.glider.lua of the three places, with the place in brackets). A choice in the menu wins over the model name; automatic (model name) goes back.
  • Where it applies: The file can hold one arrangement for the compact view and one for full screen. If the size matches the screen exactly, Glider draws it. Otherwise it takes the view with the most similar aspect ratio and scales it once to the window (note “Studio: view 800x480 adapted” for 5 s). Places that get too small are shown as number or left out. In full screen it replaces page 1 only; power and flights stay, as does the top bar.
  • Limits: Warning and alarm apply per value for the whole model, no matter how or how often the value is shown. A limit missing in the file keeps the factory limit. Sensors and channels can have limits too; they report with a tone.
  • Changes on the radio: Changes in the widget menu go to a separate file …glider.funke.lua; the studio file stays unchanged. The menu shows “Studio file: loaded” at the top. Back to studio state discards the changes made on the radio. Without a studio file the button is Back to default and resets all settings to the factory values (sensors and switches stay).
  • For the studio Glider writes an info file (…glider.info.json) after each model change with model, radio, window sizes and the sensor list.

One layout for all models

One layout for all models: put Standard.glider.lua into scripts/studio/ and every model without its own file “id.glider.lua” (id = model name) and without a menu choice uses it. Order: menu choice, model file, Standard.glider.lua, built-in display. Changes on the radio stay per model. A model named “Standard” uses its own file. The menu entry is “Default (all models)”.
